# tv-player rules
- Player first-link screens use the existing device-token code action and website sendLoginWithCode flow, with shared desktop rendering, so authenticated ownership and box approval remain unchanged.
- Primary recovery watches each connection continuously and only retries a non-progressing buffer; cancel queued reconnects on READY or resumed loading, preserve recovered video through advert/format changes, and apply learned format swaps only when a new connection is needed.
- Sports-pass recovery (DAZN and Coupang Play, matched by NFKC-normalized channel name via StreamRecovery.cushioned) uses verified channel/category identity, not numeric feed prefixes; its live-offset drift guard allows the larger cushion and same-event alternatives come from the selected Sports Guide card. Buffering reports tag the provider as dazn/coupang. Coupang alone plays plain (StreamRecovery.plainLive): no drift jump, no HLS speed easing, 15s Media3 / 30s libVLC freeze wait, because those self-restarts caused its stop-start; it also opens full screen in Media3 first like UHD (UhdChannel.ownEngine), since libVLC playback still stop-started.
- Film/whole-series votes use a separate device-token background queue; poster BM averages and counts are separate from provider ratings, with bounded batched reads and no progress bar moved to series posters.
- BM Player (Android TV/Fire TV/phone) talks to the website only through `/api/public/player` with its device token; logins arrive once via poll and live only in app storage.
- Sports guide screen (Android and desktop `renderer/sports-guide.jsx`, keep in step): day pills, Category pop-up built from the website's main/sub-categories sent with the `sports` action, one card per game, the selected card's channels grouped guide / sports passes (`passChannels`) / club channels beside it.
- Sports guide comes from published website guides via the device-token `sports` action; channel matching rules live in src/lib/player-channel-match.ts and are mirrored in MainActivity (keep in step). Per-guide Channel linking (src/lib/sports-channel-links.ts) rewrites channels on the website; apps only enforce `channelCountry`, so new naming styles need no app release.
- Provider-name equivalents are canonicalized without removing feed numbers, so Sports Pass matches cannot jump to a different numbered channel.
- VideoDecodePolicy gives affected live feeds clean-keyframe starts on hardware decoding (software lags 50fps on boxes); software only for the explicit Software setting (catch up uses hardware too), in primary and embedded backup engines; unrelated channels retain hardware defaults to protect UHD performance.
- Watched positions are stored on-device (keyed by hashed provider/login plus media kind/id) and synced per owner+login via device-token `progress`/`progress_set` (ProgressSync.java, windows-bm-player/progress-sync.cjs; newest update wins); built-in playback writes progress; bars sit on films and episodes, never the series poster.
- BM Player apps authenticate only by hashed device token at `/api/public/player`; website sends logins via one-time 10-min codes or owner-checked devices, credentials are deleted on first app poll, and DNS is a single admin-only `player_settings` row.
- BM Player saved-login selection reads the existing credential view filtered to the signed-in owner; selection is bound to that owner and passwords are never displayed.
- Screen, catch-up, guide, favourites, announcement and keypad rules live in `tv-player/app/src/main/java/uk/bmsupport/player/AGENTS.md`.
- App-wide launcher, signing, header, connection, check-in, Watch on my box and subtitle survey rules live in `tv-player/app/AGENTS.md`.
- Android Sports Guide layout, focus and refresh-dialog rules live in `tv-player/app/src/main/java/AGENTS.md`.
- Android Programme grid, Live TV voice search, Sports Guide search/voice and series detail focus rules also live in `tv-player/app/src/main/java/AGENTS.md`.
- StreamRecovery.cushioned covers DAZN, Coupang, heavy channel names and channels measured heavy or with repeated connection dropouts on this device (saved in prefs, capped); the byte memory cap on the load control always stays in place.
- Backup feed status uses BackupFeedStatus progress plus incomplete buffering, not VLC Buffering events alone; completed buffering, advancing playback and stream reopen clear the warning to avoid false stalls.
- Backup live cache derives its fixed VLC network-cache target from the primary profile minimum via BackupBufferPolicy (not a guaranteed min/max buffer); BackupStallTracker emits one duration per real stall through BufferReporter, tagged backup in decoder, flushing periodically and on exit.
- Primary/backup share PlayerActionControls for the action row, report and swap flows; backup uses Media3's original PlayerControlView with a control-only BackupControlPlayer adapter over its unchanged VLC surface, actual track/rate/seek commands and equalizer gain. Visible controls own D-pad focus; hidden controls reveal before activation and share the 3.5s watchdog.
- Linked-device spoken welcome and release-build scrambling rules live in `tv-player/app/src/main/AGENTS.md`.

- Live preview and full screen share one player both ways: Media3 uses PreviewHandoff; libVLC keeps its video attached to VlcStage on the guide window, resizing it beneath transparent BackupStageActivity controls without detaching the video or reopening media, except heavy (4K/UHD) live channels, which reopen in full screen so they get the full live buffer instead of the 1.5s preview cache. VlcPreview.Session/VlcHandoff transfers engine/audio ownership; Back returns it before the guide resumes, and stale/unclaimed transfers release the stage and stream.
- VlcStage mounts between guide content and its scrim/drawer in the guide's outer FrameLayout, never above that frame in window decor, so categories remain above the uninterrupted preview.
- Live channels open full screen in the built-in libVLC backup engine first (the original behaviour), with Media3 as the fallback. Only UHD/4K channels, Coupang Play and looped on-demand categories (UhdChannel.looped) open in Media3 first (UhdChannel.ownEngine); looped ones wait for a full keyframe before decoding (mid-picture starts jammed MediaTek chips: picture stuck, sound playing) and skip drift jumps/HLS speed easing, with the normal freeze check and jammed-chip hand-over kept; UHD/4K also skips the libVLC preview carry, and in libVLC they use longer LiveReconnect stall/no-data windows, so short 4K gaps are waited out like other IPTV apps.
- Box VPN starts off on every app start (first BoxVpn.sync sends `off` if the website still has it on); only the customer's home-screen switch turns it on. The corner VPN light shows only on full-screen player screens, never on MainActivity screens (home, guide, link).
- PlayerActivity (Media3) live/catch-up shows the same ChannelLink "Channel connection" pill and Live connections snapshot as the libVLC engine (ping every 15s, buffering = stall, reopen after first play = reconnect), shown with the controls or when Poor while buffering.
- Lost sound on live: picture advancing but no new played audio for 5s (LiveReconnect.soundLost on Android libVLC playedAbuffers / Media3 audio decoder counters; stream-recovery.cjs soundLost on desktop) reopens the channel as audio_drop, max 3 per channel; channels with no audio track are never reopened.
- Live TV splits the provider's Premier League Hub category into per-broadcaster categories (Android HubSplit.java inside cachedGet, desktop hub-split.cjs in catalogue); split ids are "<providerId>~<slug>" and map back to the provider id for per-category fetches.

- Saved-list film/episode openings await ProgressSync.beforeOpen before reading resume positions; its completion runs even offline to preserve local playback.
