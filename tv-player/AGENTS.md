# tv-player rules
- Film/whole-series votes use a separate device-token background queue; poster BM averages and counts are separate from provider ratings, with bounded batched reads and no progress bar moved to series posters.
- IntroActivity is the launcher and plays the bundled CDN-sourced opening film once per cold launch; MainActivity remains the direct destination for playback/reminders so the intro never delays them.
- BM Player (Android TV/Fire TV/phone) talks to the website only through `/api/public/player` with its device token; logins arrive once via poll and live only in app storage.
- Signed with the permanent BM key; bump versionCode/versionName and upload a new `bm-player/` build row with package_name `uk.bmsupport.player` (the update endpoint filters on it) so installs upgrade in place.
- Same tile front screen on every device; "Play with VLC" hands off to org.videolan.vlc and falls back to the built-in Media3 player.
- Built-in player controls never sit on the picture: PlayerActivity runs a once-a-second hideControls watch (InactivityPolicy.hideControls, 3.5s after the last press) because Media3's own timer never fires on live/buffering streams.
- Home-row buttons never fold a name onto a second line: smallButton() forces a single line with text that shrinks (16sp to 10sp), and smallWeight() shares the row out in proportion to each label's measured width so "Recently watched" gets more room than "Settings".
- Header pills go through headerPill() and every button() carries default margins, so pills in any row never sit flush; Live TV header order is EPG (opens the TV guide on the current category), Search TV, Voice search.
- Sports guide comes from published website guides via the device-token `sports` action; channel matching rules live in src/lib/player-channel-match.ts and are mirrored in MainActivity (keep in step).
- Provider-name equivalents are canonicalized without removing feed numbers, so Sports Pass matches cannot jump to a different numbered channel.
- Playlists download as whole-section lists on one queue (with the progress pop-up) and browse splits them by category locally, so "All" shows at once; posters never draw an overlay — the selected card paints its own ring.
- Films and Series default to "Recently added" (latest uploads first) when no sort was saved; a customer-chosen sort is still remembered per kind.
- Live preview reserves remaining height for a focusable programme-guide pane showing only Now and Up next, with no reminder control; Left from the preview or guide returns focus to the channel being watched; the full TV guide is a Sky-style grid (GuideGridView: channels × 2h time window, lazy cached EPG, 3 parallel fetches) and is the only place reminders are set.
- The TV guide's category list is a side panel (sideDrawer/showPanel/hidePanel) that slides in from the left edge, never a pop-up at the top; Back or the scrim closes it first, and the screen behind it is blocked from focus while it is open.
- Watched positions stay on-device, keyed by hashed provider/login plus media kind/id; built-in playback and VLC results (extra_position/extra_duration) write progress; bars sit on films and episodes, never the series poster.
- "Report a problem" exists only inside channel/film/episode menus; the app posts the `report` action (names, category, episode, device, version, customer text) and the website opens a Live TV or Movie/Series ticket for the linked owner.
- Self-update downloads a fresh uncached APK and installs only if its versionCode beats the installed one; release by uploading the file first, then switching the build row.
- iFollow/Scottish sports fixtures group playlist channels under each team name (teamChannels, title split on "v"), then the guide-listed channels.
- Sports guide opens with a Search manually / Voice search choice; voice matches every spoken word against event, guide and sport names. Voice buttons use the device speech service when one resolves, otherwise (Fire TV) a focused dictation box for the remote mic.
- Live connections: the poll reports login, version and the playing item (set on playback start, cleared on return to the app); the server stamps presence + Cloudflare geo via src/lib/player-live.ts, admin-only page /admin-player-live.
- The same check-in IP is judged for VPN/proxy use by src/lib/player-vpn.ts (proxycheck.io then ipapi.is, answers cached per IP) and shown in that page's VPN column; the poll that hands the app its login never waits on that lookup.
- Provider account connection counts are sampled on a separate single-flight queue; sustained excess reports use the device-token API and only an acknowledged report opens the warning activity, including during playback.
- PlayerApplication owns one foreground inactivity timer across native activities; only explicit Continue viewing dismisses the timed prompt, and exit releases all playback before opening the device home screen. External VLC is outside the app's interaction monitoring.
- Every cold open (and every new link) asks for the owner's permanent 6-digit account number, checked by the device-token `unlock` action (5 wrong tries = 15-minute lock); showHome() refuses to draw until unlocked. The unlocked flag is static so a phone lock screen recreating the activity does not re-ask while the process lives.
- BM Player apps authenticate only by hashed device token at `/api/public/player`; website sends logins via one-time 10-min codes or owner-checked devices, credentials are deleted on first app poll, and DNS is a single admin-only `player_settings` row.
- BM Player saved-login selection reads the existing credential view filtered to the signed-in owner; selection is bound to that owner and passwords are never displayed.
- Every activity is sensorLandscape so phones show the same TV-shaped layout sideways instead of squashing it portrait.
- Phones (shortest side under 500dp) shrink screen density via PhoneScale in attachBaseContext so the TV layout fits sideways; front/link/unlock screens also scroll.
- Catch up: channels with provider `tv_archive` show a clock in the TV guide channel column (Left at "now" only highlights the clock and OK opens it; tap on phones); it opens a day → programme list from `get_simple_data_table` and plays Xtream `/timeshift/` URLs (UK time) through VLC on Amazon devices only (other Android uses the built-in player, CatchupFallback.useVlc), falling back to the built-in player when VLC is missing; catch-up plays never go into Recently watched. Catch-up VLC launches add `disable_hardware`; a VLC error result (or a return under 10s with no position, CatchupFallback) replays the recording in the built-in player. Built-in catch up waits for full keyframes and prefers software decoders (hardware ones smear timeshift into blocks), falling back to hardware.
- Manual EPG time shift stores the device UTC offset; a clock change resets it to 0 so the guide is never an hour out.
- Android films/episodes ask nothing up front: the built-in player turns on existing subtitles and only then asks whether to turn them off (VLC is not asked). Windows and Mac do the same: engines report subtitle track counts and the main process pauses to ask only when tracks exist.
- Favourites and Recently watched open on Live TV / Movies / Series tabs (episodes count as Series) on Android, Windows and Mac; sports guide event rows keep a blank line between events.
- Search and voice results use resultList(): a ListView dialog with a border-only selector, one row per D-pad press, OK opens the row.
- Series seasons use bindSeriesSeasons: focus never reloads episodes, Down enters the chosen season's non-focusable episode rows, Up returns to its pill, and OK activates the selected episode; selection rings draw above rows.
- Favourites sync through the device-token `favourites`/`favourites_set` actions: one whole list per account owner and provider login (last write wins); pulled on unlock and when Favourites opens, pushed on every change; a never-stored account uploads the device's existing list, and each device's first sync merges its own favourites into the account list instead of being overwritten.
- Admin/management announcements are one-off: the server ends a row 3 minutes after sending; the newest active player_announcements row is served by the device-token `announcement` action (10s shared cache); every app checks it every 15s and draws a closable bottom bar over every screen only if the app was already open when it was sent (server age_ms vs app start) (Android adds it to the window decor; desktop shrinks screens so video never covers it); a closed announcement id is remembered per device. Android keeps the bar clear of system-bar insets, closes it on a bar tap and catches Back in dispatchKeyEvent before the screen's own Back.
- Catch-up playback builds its own player without non-IDR keyframe starts so mid-GOP timeshift recordings don't decode as blocks; live keeps the faster start.
- Major announcements are a separate player_major_announcements list (admin tab of its own), served by the device-token `major_announcements` action (30s shared cache); apps poll every 60s and show a top-right icon with an unread counter (seen ids stored per device); Android draws it only on MainActivity, never over full-screen video.
- Every text-entry box stays clear of the on-screen keypad: number-only full screens (account number) never open the system keyboard and type through the in-app NumberPad instead, because a sideways phone leaves no room above a system keyboard; other dialogs go through keepEntryVisible() (top-anchored, ADJUST_PAN, no extract UI, shrunk to the space above the measured IME inset).
