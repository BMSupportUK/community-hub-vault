# tv-player rules
- Programme grid uses a shared one-hour/quarter-hour axis with wrapped names and selected-title scrolling; start/end times stay separate so widening never changes playback or reminder routing.
- Live TV voice recognition and Fire TV dictation share LiveVoiceSearch grouping; headers are disabled resultList rows, categories retain provider IDs and events reuse existing Sports Guide channel selection without opening a second stream.
- Sports Guide opening/manual refresh uses its own status dialog through listings, catalogue and selected-channel matching; periodic refresh stays unobtrusive, and completion, failure or exit clears the dialog. Sports body/card rows disable baseline alignment to keep unequal columns inside their bounds.
- Sports event selections restore at the padded list origin and reveal clipped selected cards after remote navigation/focus; viewport checks must use an attached scrolling list, not just detached row measurements.
- DAZN recovery uses verified channel/category identity, not numeric feed prefixes; its live-offset drift guard allows the larger cushion and same-event alternatives come from the selected Sports Guide card.
- Film/whole-series votes use a separate device-token background queue; poster BM averages and counts are separate from provider ratings, with bounded batched reads and no progress bar moved to series posters.
- IntroActivity is the launcher and plays the bundled CDN-sourced opening film once per cold launch; MainActivity remains the direct destination for playback/reminders so the intro never delays them.
- BM Player (Android TV/Fire TV/phone) talks to the website only through `/api/public/player` with its device token; logins arrive once via poll and live only in app storage.
- Signed with the permanent BM key; bump versionCode/versionName and upload a new `bm-player/` build row with package_name `uk.bmsupport.player` (the update endpoint filters on it) so installs upgrade in place.
- Same tile front screen on every device; external VLC is removed from the app (no menu option, setting or catch-up handoff) — the built-in player and its in-app backup engine play everything.
- Built-in player controls never sit on the picture: the once-a-second watchdog hides both Media3 and its sibling controls row 3.5s after input, regardless of Media3 visibility state; synchronize the row on controller transitions because native timers alone are unreliable on live/buffering streams.
- Home-row buttons never fold a name onto a second line: smallButton() forces a single line with text that shrinks (16sp to 10sp), and smallWeight() shares the row out in proportion to each label's measured width so "Recently watched" gets more room than "Settings".
- Header pills go through headerPill() and every button() carries default margins, so pills in any row never sit flush; Live TV header order is EPG (opens the TV guide on the current category), Search TV, Voice search.
- Sports guide screen (Android and desktop `renderer/sports-guide.jsx`, keep in step): day pills, Category pop-up built from the website's main/sub-categories sent with the `sports` action, one card per game, the selected card's channels grouped guide / sports passes (`passChannels`) / club channels beside it.
- Sports header disables baseline alignment and assigns remaining width to a single-line category pill, preventing long website guide names from expanding the header and starving the games area.
- Native Sports Guide intercepts horizontal remote keys before default focus search and restores playback channel selection by channel ID, so date controls cannot intercept fixture-to-channel navigation or refresh lose the watched row.
- Sports guide comes from published website guides via the device-token `sports` action; channel matching rules live in src/lib/player-channel-match.ts and are mirrored in MainActivity (keep in step). Per-guide Channel linking (src/lib/sports-channel-links.ts) rewrites channels on the website; apps only enforce `channelCountry`, so new naming styles need no app release.
- Provider-name equivalents are canonicalized without removing feed numbers, so Sports Pass matches cannot jump to a different numbered channel.
- Boxing sports matches use the stable numbered feed before the pipe, never mutable programme/replay text, so stale playlist names cannot redirect a fixture.
- VideoDecodePolicy gives affected live feeds clean-keyframe starts on hardware decoding (software lags 50fps on boxes); software stays for catch up and the explicit Software setting, in primary and embedded backup engines; unrelated channels retain hardware defaults to protect UHD performance.
- Playlists download as whole-section lists on one queue (with the progress pop-up) and browse splits them by category locally, so "All" shows at once; posters never draw an overlay — the selected card paints its own ring.
- Films and Series default to "Recently added" (latest uploads first) when no sort was saved; a customer-chosen sort is still remembered per kind.
- Watched positions are stored on-device (keyed by hashed provider/login plus media kind/id) and synced per owner+login via device-token `progress`/`progress_set` (ProgressSync.java, windows-bm-player/progress-sync.cjs; newest update wins); built-in playback and VLC results (extra_position/extra_duration) write progress; bars sit on films and episodes, never the series poster.
- "Report a problem" lives on the built-in player screen (a button shown with the controls), never in play menus; the app posts the `report` action (names, category, episode, device, version, customer text) and the website opens a Live TV or Movie/Series ticket for the linked owner.
- Self-update downloads a fresh uncached APK and installs only if its versionCode beats the installed one; release by uploading the file first, then switching the build row.
- iFollow/Scottish sports fixtures group playlist channels under each team name (teamChannels, title split on "v"), then the guide-listed channels.
- Sports guide opens with a Search manually / Voice search choice; voice matches every spoken word against event, guide and sport names. Voice buttons use the device speech service when one resolves, otherwise (Fire TV) a focused dictation box for the remote mic.
- SportsVoiceSearch owns spoken Sports Guide matching with desktop-equivalent filler removal and spaced/joined name matching, so speech-service output does not require exact sentence matching.
- Live connections: the poll reports login, version and the playing item (set on playback start, cleared on return to the app); the server stamps presence + Cloudflare geo via src/lib/player-live.ts, admin-only page /admin-player-live. Polls run only while a BM Player screen is visible (or external VLC is playing a handoff), so a backgrounded app drops off within the 3-minute live window.
- The same check-in IP is judged for VPN/proxy use by src/lib/player-vpn.ts (proxycheck.io then ipapi.is, answers cached per IP) and shown in that page's VPN column; the poll that hands the app its login never waits on that lookup.
- Provider account connection counts are sampled on a separate single-flight queue; sustained excess reports use the device-token API and only an acknowledged report opens the warning activity, including during playback.
- PlayerApplication owns one foreground inactivity timer across native activities; only explicit Continue viewing dismisses the timed prompt, and exit releases all playback before opening the device home screen. External VLC is outside the app's interaction monitoring.
- Every cold open (and every new link) asks for the owner's permanent 6-digit account number, checked by the device-token `unlock` action (5 wrong tries = 15-minute lock); showHome() refuses to draw until unlocked. The unlocked flag is static so a phone lock screen recreating the activity does not re-ask while the process lives.
- BM Player apps authenticate only by hashed device token at `/api/public/player`; website sends logins via one-time 10-min codes or owner-checked devices, credentials are deleted on first app poll, and DNS is a single admin-only `player_settings` row.
- BM Player saved-login selection reads the existing credential view filtered to the signed-in owner; selection is bound to that owner and passwords are never displayed.
- Every activity is sensorLandscape so phones show the same TV-shaped layout sideways instead of squashing it portrait.
- Phones (shortest side under 500dp) shrink screen density via PhoneScale in attachBaseContext so the TV layout fits sideways; front/link/unlock screens also scroll.
- Screen, catch-up, guide, favourites, announcement and keypad rules live in `tv-player/app/src/main/java/uk/bmsupport/player/AGENTS.md`.
- Background website check-ins (poll, announcements, sports refresh, buffering flush) go through Checkin.java / windows-bm-player/checkin.cjs: ±20% jitter, random start offset, doubling back-off to 5 min on 429/5xx/timeouts, Retry-After honoured, and the poll`s `slow` multiplier (player_settings.checkin_slowdown, 1–10) stretches every timer so load can be eased without an app release.
- Live TV EPG reads provider short/full-day tables except non-official sports/club feeds, which first request saved website fixtures; fixture responses never get overwritten by provider expansion. Country imports/category refresh stay retired.
