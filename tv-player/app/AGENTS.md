# tv-player app module rules
- Signed with the permanent BM key; bump versionCode/versionName and upload a new `bm-player/` build row with package_name `uk.bmsupport.player` (the update endpoint filters on it) so installs upgrade in place.
- Same tile front screen on every device; external VLC is removed from the app (no menu option, setting or catch-up handoff) — the built-in player and its in-app backup engine play everything.
- Built-in player controls never sit on the picture: the once-a-second watchdog hides both Media3 and its sibling controls row 3.5s after input, regardless of Media3 visibility state; synchronize the row on controller transitions because native timers alone are unreliable on live/buffering streams.
- Home-row buttons never fold a name onto a second line: smallButton() forces a single line with text that shrinks (16sp to 10sp), and smallWeight() shares the row out in proportion to each label's measured width so "Recently watched" gets more room than "Settings".
- Header pills go through headerPill() and every button() carries default margins, so pills in any row never sit flush; Live TV header order is View EPG on phones (opens the guide full screen), then Search TV, Voice search; TV boxes show Search TV and Voice search.
- Playlists download as whole-section lists on one queue (with the progress pop-up) and browse splits them by category locally, so "All" shows at once; posters never draw an overlay — the selected card paints its own ring.
- Films and Series default to "Recently added" (latest uploads first) when no sort was saved; a customer-chosen sort is still remembered per kind.
- Self-update downloads a fresh uncached APK and installs only if its versionCode beats the installed one; release by uploading the file first, then switching the build row.
- IntroActivity is the launcher and plays the bundled CDN-sourced opening film once per cold launch; MainActivity remains the direct destination for playback/reminders so the intro never delays them.
- Live connections: the poll reports login, version and the playing item (set on playback start, cleared on return to the app); the server stamps presence + Cloudflare geo via src/lib/player-live.ts, admin-only page /admin-player-live. Polls run only while a BM Player screen is visible (or external VLC is playing a handoff), so a backgrounded app drops off within the 3-minute live window.
- The same check-in IP is judged for VPN/proxy use by src/lib/player-vpn.ts (proxycheck.io then ipapi.is, answers cached per IP) and shown in that page's VPN column; the poll that hands the app its login never waits on that lookup.
- Provider account connection counts are sampled on a separate single-flight queue; sustained excess reports use the device-token API and only an acknowledged report opens the warning activity, including during playback.
- PlayerApplication owns one foreground inactivity timer across native activities; only explicit Continue viewing dismisses the timed prompt, and exit releases all playback before opening the device home screen. External VLC is outside the app's interaction monitoring.
- First open (no saved login) shows a 6-digit link code entered on the website; a login delivered by the website counts as the sign-in and is remembered against the device token. Otherwise the box asks for the 6-digit account number (5 wrong tries = 15-minute lock), only again after log out, unlinking or cleared data. Website approval requests/QR are retired server-side.
- Every activity is sensorLandscape so phones show the same TV-shaped layout sideways instead of squashing it portrait.
- Phones (shortest side under 500dp) shrink screen density via PhoneScale in attachBaseContext so the TV layout fits sideways; front/link/unlock screens also scroll.
- Search and voice results use resultList(): a ListView dialog with a border-only selector, one row per D-pad press, OK opens the row.
- Every text-entry box stays clear of the on-screen keypad: number-only full screens (account number) never open the system keyboard and type through the in-app NumberPad instead, because a sideways phone leaves no room above a system keyboard; other dialogs go through keepEntryVisible() (top-anchored, ADJUST_PAN, no extract UI, shrunk to the space above the measured IME inset).
- Films/Series on every BM Player (Android MediaHero, desktop MediaHero in app.jsx): details panel on top (backdrop, rating · year · length · genre, cast, director, plot from get_vod_info/get_series_info, cached), Sort row, then a full-width poster grid under the category name. Android has no top Category pill: the category sidebar opens highlighted on entry and from row-edge Left; desktop keeps its Category pill beside Search/Voice.
- Favourites and Recently watched open on Live TV / Movies / Series tabs (episodes count as Series) on Android, Windows and Mac; sports guide event rows keep a blank line between events.
- Episode cards show their number on its own line and that episode's title beneath it, capped at two lines; never one clipped "E7. Title" line, and no invented number line when the provider supplies none.
- The saved app password is sealed with an Android Keystore key (SecureLogin.java); a copied password that can't be opened counts as no login. Poll sends the signer SHA-256 as `sig`; a 401 clears token, login and unlock.
- First sign-in displays the device code from the device-token `code` action for entry on the authenticated website Link Device page; polling receives the login. No sign-in QR or app-side code entry. No-account chat and 2FA remain retired; private desktop IPC stays gated.
- Inactivity prompt deadlines survive activity/dialog destruction and expire after one unanswered minute, preventing Fire OS recreation from restarting the three-hour timeout.
- Watched = 90%+ of a film/episode (WatchProgress.finished, desktop percent>=90) and shows a green "✓ Watched" under the bar; episode cards strip the series name and S01E03-style codes via EpisodeName.clean / episode-title.cjs cleanEpisodeName, kept in step.
- Background website check-ins (poll, announcements, sports refresh, buffering flush) go through Checkin.java / windows-bm-player/checkin.cjs: ±20% jitter, random start offset, doubling back-off to 5 min on 429/5xx/timeouts, Retry-After honoured, and the poll`s `slow` multiplier (player_settings.checkin_slowdown, 1–10) stretches every timer so load can be eased without an app release.
- "Watch on my box" (What to Watch) queues a player_watch_requests row only for the owner's Android/Fire TV/phone box seen within the live window; the device-token `announcement` reply hands it over once (2-min freshness) and the app opens it by provider id, then exact title, then search.
- Live subtitle survey: PlayerActivity sends one `subtitle_check` (track count + languages) per live play once video tracks are known; the website tallies it in service-role-only player_channel_subtitles. Nothing is shown to viewers.
- Leaving the app in the background never resets the linked-device pass (pinPassed); only a real exit or process end shows the family link check again. Home shows Multi-screen straight from the saved account-info max_connections (also saved by Settings › Account info), so a slow or failed check never hides it.
- Multi-screen panes play in libVLC (VlcPreview inserted under the pane label, mute follows the highlighted pane) like full-screen live TV; the per-pane Media3 players stay idle.
- Announcement icon and bottom bar appear only via MainActivity.signedInScreen(): signed in, unlocked and past today's 2FA; never on link/account-number/2FA/expired/maintenance screens.
- Stuck video chip guard: every Live TV preview channel change drops the stage SurfaceView for a fresh one; a preview whose rendered-frame count stops for 3s while READY restarts itself (max 3 per channel) and a frozen preview is never carried to full screen.
