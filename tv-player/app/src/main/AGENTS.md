# tv-player main source set rules
- Admin/management announcements are one-off: the server ends a row 3 minutes after sending; the newest active player_announcements row is served by the device-token `announcement` action (10s shared cache); every app checks it every 15s and draws a closable bottom bar over every screen only if the app was already open when it was sent (server age_ms vs app start) (Android adds it to the window decor; desktop shrinks screens so video never covers it); a closed announcement id is remembered per device. Android keeps the bar clear of system-bar insets, closes it on a bar tap and catches Back in dispatchKeyEvent before the screen's own Back.
- Major announcements are a separate player_major_announcements list (admin tab of its own), served by the device-token `major_announcements` action (30s shared cache); apps poll every 60s and show a top-right icon with an unread counter (seen ids stored per device); Android draws it as a round 44dp button with a red count bubble only on the MainActivity home screen, and every header keeps PlayerApplication.MAJOR_ICON_SLOT_DP free on its right so it never covers buttons, never over full-screen video; a signed-out, still-locked (account number not yet entered) or unlinked app shows no icon and keeps no list; the server returns an empty list to devices not linked to a member (Windows/Mac gate on the unlocked state). The icon opens a full-screen "News & Announcements" page of picture cards (title under each) that open the full text; pictures are optional uploads to the private player-announcements bucket and reach apps as 12-hour signed image_url links in the cached reply.
- Sound booster: removed on every device from 5.25 — SoundBoost.fixed() is always true, so the level is fixed at the default (Medium) and the booster button and Settings entry are hidden everywhere (it made no audible difference on any box). The Medium level still drives Android LoudnessEnhancer (limiter, so peaks don't clip) on Media3's decoded PCM session (no Dolby passthrough) and on each libVLC instance's own generated session passed as --audiotrack-session-id, with libVLC volume at unity and equalizer detached; raw libVLC gain is only the fallback when no enhancer attaches. The box's own media volume is never changed by the app (5.22 forced it to full and was far too loud). Preview/Multi-screen mute always wins. External players are untouched.
- Live connections: the poll reports login, version and the playing item (set on playback start, cleared on return to the app); the server stamps presence + Cloudflare geo via src/lib/player-live.ts, admin-only page /admin-player-live. The reported ping times a fresh connection to the playing stream's own server (np_host/np_port noted at playback start, streamPingMs), never the website check-in round-trip. Polls run only while a BM Player screen is visible, so a backgrounded app drops off within the 3-minute live window.
- The same check-in IP is judged for VPN/proxy use by src/lib/player-vpn.ts (proxycheck.io then ipapi.is, answers cached per IP) and shown in that page's VPN column; the poll that hands the app its login never waits on that lookup.
- Home-screen themes: owner-managed player_themes rows (admin-only RLS, Themes section of the BM Player dashboard) are served to apps by the device-token `themes` action with pictures under public/player-themes; apps only change the home background (Android PlayerTheme.java saves the picture on the box, desktop theme.cjs accepts bmsupport.uk pictures only) and drop a switched-off/deleted theme back to standard on the next check. Themed homes keep the same layout: tiles/buttons turn see-through in place with the theme row's hex accent on the selected outline, pictures are top-anchored, and Settings offers Light/Medium/Strong shading (lightest in the middle); Android PlayerTheme and desktop theme.cjs hold the shading values, keep them in step.
- Linked-device spoken welcome: apps request device-token `welcome_voice` once per app start after the link is confirmed; the website makes and caches the MP3 with ElevenLabs, so no voice key ships in an app.
- Release builds scramble our own code: Android apps use R8 (`minifyEnabled true`, `proguard-rules.pro` keeps third-party libraries); Windows/Mac release steps run javascript-obfuscator over the staged `.cjs` and renderer bundle (never the repo source) and then re-check every module still loads. Keep the R8 mapping file privately for crash traces.
