# tv-player Java source rules
- Catch up: channels with provider `tv_archive` show a clock in the TV guide channel column (Left at "now" only highlights the clock and OK opens it; tap on phones); it opens a day → programme list from `get_simple_data_table` and plays Xtream `/timeshift/` URLs (UK time) through the built-in player on every device (VLC was removed from the app); catch-up plays never go into Recently watched. Built-in catch up waits for full keyframes and uses the hardware decoder like everything else (software made picture lag sound); only the Settings decoder choice forces software. Catch up opens CatchupStart.offset minutes (Settings, default 2) after the listed start with the requested length extended to match, shows CatchupSeek "⏪ Back 1 min" + "⏩ Fast forward" (presses stack +1 min each, long-press +5, one reopen 1.5s after the last press, never earlier than the listed start; no jump-to-next-programme because guide slots are not real starts), up 20s after each press; where it lands is remembered per channel (CatchupStart.offsetFor) as that channel's opening offset, and its skip buttons reopen the timeshift a minute later or earlier (it cannot seek in place); every reopen resets the started flag so the stopped recording's late end event is ignored, and drop-out recovery resumes at the next whole minute, never rounding back.
- Series seasons use bindSeriesSeasons: focus never reloads episodes, Down enters the chosen season's non-focusable episode rows, Up returns to its pill, and OK activates the selected episode; selection rings draw above rows.
