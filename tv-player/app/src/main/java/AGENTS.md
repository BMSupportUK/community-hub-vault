# tv-player Java source rules
- Catch up: channels with provider `tv_archive` show a clock in the TV guide channel column (Left at "now" only highlights the clock and OK opens it; tap on phones); it opens a day → programme list from `get_simple_data_table` and plays Xtream `/timeshift/` URLs (UK time) through the built-in player on every device (libVLC remains only as the built-in backup engine); catch-up plays never go into Recently watched. Built-in catch up waits for full keyframes and uses the hardware decoder like everything else (software made picture lag sound); only the Settings decoder choice forces software. Catch up opens CatchupStart.offset minutes (Settings, default 2) after the listed start with the requested length extended to match, shows CatchupSeek "⏪ Back 1 min" + "⏩ Fast forward" (presses stack +1 min each, long-press +5, one reopen 1.5s after the last press, never earlier than the listed start; no jump-to-next-programme because guide slots are not real starts), up 20s after each press; where it lands is remembered per channel (CatchupStart.offsetFor) as that channel's opening offset, and its skip buttons reopen the timeshift a minute later or earlier (it cannot seek in place); every reopen resets the started flag so the stopped recording's late end event is ignored, and drop-out recovery resumes at the next whole minute, never rounding back.
- Series seasons use bindSeriesSeasons: focus never reloads episodes, Down enters the chosen season's non-focusable episode rows, Up returns to its pill, and OK activates the selected episode; selection rings draw above rows.
- Catch-up playback builds its own player without non-IDR keyframe starts so mid-GOP timeshift recordings don't decode as blocks; live keeps the faster start.
- Sports Guide opening/manual refresh uses its own status dialog through listings, catalogue and selected-channel matching; periodic refresh stays unobtrusive, and completion, failure or exit clears the dialog. Sports body/card rows disable baseline alignment to keep unequal columns inside their bounds.
- Sports event selections restore at the padded list origin and reveal clipped selected cards after remote navigation/focus; viewport checks must use an attached scrolling list, not just detached row measurements.
- Sports header disables baseline alignment and assigns remaining width to a single-line category pill, preventing long website guide names from expanding the header and starving the games area.
- Native Sports Guide intercepts horizontal remote keys before default focus search and restores playback channel selection by channel ID, so date controls cannot intercept fixture-to-channel navigation or refresh lose the watched row.
- The guide-load drawer snapshot must stay cheap: never call streamUrls() (Keystore binder) or categoryName() (reads cache file) per channel; use the loaded category rows. Both caused ANRs/slow EPG loads.
- VPN off is applied on the device first (tunnel down, userOff) before the website is told, and sync re-sends "off" instead of bringing the tunnel back while userOff, because the off request travels through a possibly broken tunnel.
- Adult categories are listed only when the cached full playlist has streams in them (AdultCategoryContent via orderedCategories and the category editor), because panels send every category name to non-adult packages. Films/Series category drawers have no Close button: Left, Back or the scrim close them, like the Live TV guide.
