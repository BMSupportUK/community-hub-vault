# tv-player Java source rules
- Catch up: opened only from the home-screen ⏰ Catch up button on every player (categories with `tv_archive` channels → channel); the TV guide and play menus show no clock or catch-up entry. It opens a day → programme list from `get_simple_data_table` and plays Xtream `/timeshift/` URLs (UK time) through the built-in player on every device (libVLC remains only as the built-in backup engine); catch-up plays never go into Recently watched. Built-in catch up waits for full keyframes and uses the hardware decoder like everything else (software made picture lag sound); only the Settings decoder choice forces software. Catch up opens CatchupStart.offset minutes (Settings, default 2) after the listed start with the requested length extended to match, shows CatchupSeek "⏪ Back 1 min" + "⏩ Fast forward" (presses stack +1 min each, long-press +5, one reopen 1.5s after the last press, never earlier than the listed start; no jump-to-next-programme because guide slots are not real starts), shown at the bottom above the playback bar and, like Windows, hidden after 3.5s without input and brought back by any key or touch (never taking focus); after a skip reopen the sound stays silent until the first new picture is drawn (10s cap); where it lands is remembered per channel (CatchupStart.offsetFor) as that channel's opening offset, and its skip buttons reopen the timeshift a minute later or earlier (it cannot seek in place); every reopen resets the started flag so the stopped recording's late end event is ignored, and drop-out recovery resumes at the next whole minute, never rounding back.
- Series seasons use bindSeriesSeasons: focus never reloads episodes, Down enters the chosen season's non-focusable episode rows, Up returns to its pill, and OK activates the selected episode; selection rings draw above rows.
- Series detail entry focuses its top action; asynchronous episode insertion never steals focus or scrolls past the title, while deliberate remote navigation still reveals episodes.
- Catch-up playback builds its own player without non-IDR keyframe starts so mid-GOP timeshift recordings don't decode as blocks; live keeps the faster start.
- Programme grid (Android) uses a Sky-style fixed time scale: the 2h window always fills the grid width and never depends on listings, so boxes cannot move; titles cap at two ellipsized lines and the full name lives in the info panel. Start/end times stay unscaled for playback and reminder routing.
- Live TV voice recognition and Fire TV dictation share category/channel-only LiveVoiceSearch grouping without sports requests; headers are disabled resultList rows and categories retain provider IDs. Sports Guide voice matching remains separate.
- Sports Guide opening/manual refresh uses its own status dialog through listings, catalogue and selected-channel matching; periodic refresh stays unobtrusive, and completion, failure or exit clears the dialog. Sports body/card rows disable baseline alignment to keep unequal columns inside their bounds.
- Sports event selections restore at the padded list origin and reveal clipped selected cards after remote navigation/focus; viewport checks must use an attached scrolling list, not just detached row measurements.
- Sports header disables baseline alignment and assigns remaining width to a single-line category pill, preventing long website guide names from expanding the header and starving the games area.
- Native Sports Guide intercepts horizontal remote keys before default focus search and restores playback channel selection by channel ID, so date controls cannot intercept fixture-to-channel navigation or refresh lose the watched row.
- Sports guide opens with a Search manually / Voice search choice; voice matches every spoken word against event, guide and sport names. Voice search is hidden on Amazon Fire TV (VoiceEntry.available false; its remote mic proved unusable from apps), so Amazon gets typed search only. Other devices retain their resolved speech service.
- SportsVoiceSearch owns spoken Sports Guide matching with desktop-equivalent filler removal and spaced/joined name matching, so speech-service output does not require exact sentence matching.
- Boxing sports matches use the stable numbered feed before the pipe, never mutable programme/replay text, so stale playlist names cannot redirect a fixture.
- iFollow/Scottish sports fixtures group playlist channels under each team name (teamChannels, title split on "v"), then the guide-listed channels.
- Sports Guide previews a channel in its own preview box first (OK previews, OK again on the same channel carries it full screen), reusing the Live TV stage/hand-back so neither direction reconnects.
- Report a problem lives on the built-in player screen (bottom-left button, shown with the controls, ADJUST_PAN pop-up, no keepEntryVisible resizing which flickered phones); play menus never carry it — the series page keeps its own button. The app posts the `report` action (names, category, episode, device, version, customer text) and the website opens a Live TV or Movie/Series ticket for the linked owner.
- The home-screen 50Hz button also resets video: it releases the preview and any carried/hand-back players and drops the stage surface before the display mode changes.
- The guide-load drawer snapshot must stay cheap: never call streamUrls() (Keystore binder) or categoryName() (reads cache file) per channel; use the loaded category rows. Both caused ANRs/slow EPG loads.
- VPN off is applied on the device first (tunnel down, userOff) before the website is told, and sync re-sends "off" instead of bringing the tunnel back while userOff, because the off request travels through a possibly broken tunnel.
- Adult categories are listed only when the cached full playlist has streams in them (AdultCategoryContent via orderedCategories and the category editor), because panels send every category name to non-adult packages. Films/Series category drawers have no Close button: Left, Back or the scrim close them, like the Live TV guide.
