# tv-player activity rules
- VPN Settings and playback use VpnServerList for lowest-raw-traffic-first rows with numeric readings and relative bars; bars compare listed servers, never imply an undocumented capacity percentage.
- Upcoming programme selections and their reminder icons confirm reminder changes before preview routing; current programmes/channel labels retain normal playback behaviour.
- Live channel play menus include Catch up only when archiveDays > 0 and open the existing channel archive; preserve Cast/external option indices and return to the selected Live TV category, because Left now opens categories on boxes.
- Channel/preview EPG shares FixtureGuide: non-official sports/club feeds first read saved website fixtures, authoritative responses bypass provider expansion, ordinary/unmatched channels use provider short/full-day tables. Category entry never calls country-refresh endpoints.
- Phone Live TV (wirePhoneLive, PhoneLiveRow) is its own layout while TV boxes keep the always-visible grid: category chips + Search in the header, preview and programme beside a channel list (logo, now + progress, next, favourite star; tap previews, tap again opens the menu), and a bottom bar with the Preview/Play menu button plus Channels / Guide / Favourites tabs. Guide shows the full-height grid (replaces View EPG); Favourites is a virtual category id `fav` that never becomes the saved category. LiveGuideHeaderTest covers both modes. Later lines describing the phone View EPG pop-up are superseded by this rule.
- Live TV on phones was the Sky-style guide screen (showTvGuide(cat, live=true)); TV boxes (Android/Google TV/Fire TV) use the same guide screen with the grid always visible: preview top-left, programme info beside it (title, times, progress/minutes left, description, Next line, favourite star, category) with Search TV/Voice search pills top-right, date above the grid. Box top row is non-baseline-aligned (baseline alignment scatters the info text) and the info panel is a stack of single-line or line-capped rows with minutes left inside the time text (side-by-side text views squeeze and stretch the panel), preview ~30% width capped at 32% height, and a slim date row carries compact miniPill ◀ 24h / Now / 24h ▶ controls. Guide screen details: preview box on top, GuideGridView below, categories in the slide-out side panel; OK on an on-now programme previews it, OK again opens the channel menu; the home screen has no separate TV guide tile; there is no persistent left-edge Categories tab on phones or boxes — TV boxes get a bold "◀ Press Left on your remote to list the categories" hint beside the Category pill, shown only while the selection is on the programme that is on now (on future listings Left steps back, so the hint hides), and phones keep the Categories pill in the View EPG pop-up bar; on phones the preview sits alone with no guide grid beneath it; the "View EPG" pill in the header row before Search TV opens the guide full screen, and the Now/Day controls live in that pop-up's bar (the normal view drops that row); the guide is a Sky-style grid (GuideGridView: channels × 2h time window (3h on phones), lazy cached EPG, 3 parallel fetches) and is the only place reminders are set.
- Full-screen live playback on TV/Fire TV boxes: Left with the controls hidden slides the guide's category/channel drawer over the playing picture (LiveDrawerData snapshot taken when the TV guide loads); the picture keeps playing underneath, Back or Left closes it, and picking a channel sets LiveDrawerData.pendingPick and finishes so the main screen hands the old stream back to the guide preview and opens the new channel through the normal playback path. Films, episodes, catch up and phones are unchanged.
- The TV guide's category list is a side panel (sideDrawer/showPanel/hidePanel) that slides in from the left edge, never a pop-up at the top; no persistent left-edge Categories tab is drawn. On TV/Fire TV boxes Left at the current programme opens it, while on a future programme Left steps back one listing; the Category pill is display-only. Closing restores grid focus without changing row/time/scroll; selecting the same category preserves position, while a different category starts at its first channel. The drawer's scoped return-focus target restores focus immediately and after its closing animation so Android cannot send it to Search TV. On phones LiveChannelDrawer slides from categories to their channel list without closing the panel, and channel selection aligns the grid and starts its preview. Back or the scrim closes the drawer first, and the screen behind it is blocked from focus while it is open. Phone Left/time/catch-up navigation remains unchanged.
- GuideGridView handles vertical (rows) and horizontal (30-min time steps, never before now) touch drags itself (no outer ScrollView around the grid), suppresses selection after swiping, and retains remote row/page navigation so the preview remains above the scrolling guide.
- Phone guide screens apply GuideSafeArea system/gesture/cutout insets to their outer frame; never disable Android navigation, and cancelled guide touches cannot select a channel.
- Catch-up and series season rules (day → programme list, timeshift URLs, CatchupStart offset and skip buttons, bindSeriesSeasons focus) live in `tv-player/app/src/main/java/AGENTS.md`.
- Drawer snapshot, VPN off, adult category rules: `tv-player/app/src/main/java/AGENTS.md`.
- Report a problem, Sports Guide preview and 50Hz reset rules also live in `tv-player/app/src/main/java/AGENTS.md`.
- Android films/episodes ask nothing up front: the built-in player turns on existing subtitles and only then asks whether to turn them off; both engines also show a 💬 Subtitles button (PlayerActionControls) to switch them off or pick another track at any time. Windows and Mac do the same: engines report subtitle track counts and the main process pauses to ask only when tracks exist.
- A Live TV preview that reaches playing reports itself as Live TV viewing (np_* now-playing, np_preview flag) until it stops, so it shows on Live connections; the website never credits previews toward viewing hours (watching_preview skips the watch credit).
- Live TV previews never start on highlight (Android: the guide grid's highlight never previews in live mode): the preview box shows the family-on-sofa picture (father pointing a remote at the TV, no text in the picture) until a channel is clicked/OK'd; the instruction line sits under the box (phones title the info "Current programme", show the chosen category under it and put a "▶ Preview channel" button beneath those details); stopPreview shows the picture again. OK again on the previewing channel opens its menu; on phones a single tap on a playing preview opens that menu and the button becomes "▶ Play menu" (previewStarted/previewStopped keep the label in step).
- Playback-engine rules (anti-freeze and live cushion, favourites sync, sound booster, guide listings, DLNA cast, backup hand-over, player controls, EPG time shift, swap channel, shared-login takeover) live in `tv-player/app/src/main/java/uk/bmsupport/AGENTS.md`.
- Search/voice, keypad, tab and Films/Series layout rules live in `tv-player/app/AGENTS.md`.
- Announcement rules (admin/management and major announcements) live in `tv-player/app/src/main/AGENTS.md`.
- TV boxes draw the live preview on one window-decor SurfaceView "stage" over the preview box; opening full screen from it grows the stage to the screen under the see-through PlayerStageActivity (PlayerView with no surface) and Back hands the player back and shrinks it, because changing surface restarts many boxes' decoders (black). Phones and non-carried opens keep PreviewHandoff + PreviewSnapshot into the normal PlayerActivity.
