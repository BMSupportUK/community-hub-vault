# tv-player activity rules
- Phone Live TV uses its dedicated View EPG screen mode while TV boxes keep the always-visible grid, so the guide has usable space on short phone screens; LiveGuideHeaderTest covers both modes.
- Live TV on phones was the Sky-style guide screen (showTvGuide(cat, live=true)); TV boxes (Android/Google TV/Fire TV) use the same guide screen with the grid always visible: preview top-left, programme info beside it (title, times, progress/minutes left, description, Next line, favourite star, category) with Search TV/Voice search pills top-right, date above the grid. Box top row is non-baseline-aligned (baseline alignment scatters the info text) and the info panel is a stack of single-line or line-capped rows with minutes left inside the time text (side-by-side text views squeeze and stretch the panel), preview ~30% width capped at 32% height, and a slim date row carries compact miniPill ◀ 24h / Now / 24h ▶ controls. Guide screen details: preview box on top, GuideGridView below, categories in the slide-out side panel; OK on an on-now programme previews it, OK again opens the channel menu; the home screen has no separate TV guide tile; phones get a left-edge "Categories" tab (TV boxes have no left tab; their only category control is the Category pill after the day jumps) (no category button in the Now/Day row); on phones the preview sits alone with no guide grid beneath it; the "View EPG" pill in the header row before Search TV opens the guide full screen, and the Now/Day controls live in that pop-up's bar (the normal view drops that row); the guide is a Sky-style grid (GuideGridView: channels × 2h time window (3h on phones), lazy cached EPG, 3 parallel fetches) and is the only place reminders are set.
- The TV guide's category list is a side panel (sideDrawer/showPanel/hidePanel) that slides in from the left edge, never a pop-up at the top; On TV boxes the Category pill after the day jumps is the only way in, and picking a category loads its channels into the guide and closes the panel; on phones LiveChannelDrawer slides from categories to their channel list without closing the panel, and channel selection aligns the grid and starts its preview. Back or the scrim closes the drawer first, and the screen behind it is blocked from focus while it is open.
- GuideGridView handles vertical (rows) and horizontal (30-min time steps, never before now) touch drags itself (no outer ScrollView around the grid), suppresses selection after swiping, and retains remote row/page navigation so the preview remains above the scrolling guide.
- Phone guide screens apply GuideSafeArea system/gesture/cutout insets to their outer frame; never disable Android navigation, and cancelled guide touches cannot select a channel.
- Catch up: channels with provider `tv_archive` show a clock in the TV guide channel column (Left at "now" only highlights the clock and OK opens it; tap on phones); it opens a day → programme list from `get_simple_data_table` and plays Xtream `/timeshift/` URLs (UK time) through the built-in player on every device (VLC was removed from the app); catch-up plays never go into Recently watched. Built-in catch up waits for full keyframes and prefers software decoders (hardware ones smear timeshift into blocks), falling back to hardware.
- Android films/episodes ask nothing up front: the built-in player turns on existing subtitles and only then asks whether to turn them off (VLC is not asked). Windows and Mac do the same: engines report subtitle track counts and the main process pauses to ask only when tracks exist.
- Favourites and Recently watched open on Live TV / Movies / Series tabs (episodes count as Series) on Android, Windows and Mac; sports guide event rows keep a blank line between events.
- Search and voice results use resultList(): a ListView dialog with a border-only selector, one row per D-pad press, OK opens the row.
- Series seasons use bindSeriesSeasons: focus never reloads episodes, Down enters the chosen season's non-focusable episode rows, Up returns to its pill, and OK activates the selected episode; selection rings draw above rows.
- Admin/management announcements are one-off: the server ends a row 3 minutes after sending; the newest active player_announcements row is served by the device-token `announcement` action (10s shared cache); every app checks it every 15s and draws a closable bottom bar over every screen only if the app was already open when it was sent (server age_ms vs app start) (Android adds it to the window decor; desktop shrinks screens so video never covers it); a closed announcement id is remembered per device. Android keeps the bar clear of system-bar insets, closes it on a bar tap and catches Back in dispatchKeyEvent before the screen's own Back.
- Catch-up playback builds its own player without non-IDR keyframe starts so mid-GOP timeshift recordings don't decode as blocks; live keeps the faster start.
- Major announcements are a separate player_major_announcements list (admin tab of its own), served by the device-token `major_announcements` action (30s shared cache); apps poll every 60s and show a top-right icon with an unread counter (seen ids stored per device); Android draws it as a round 44dp button with a red count bubble only on MainActivity, and every header keeps PlayerApplication.MAJOR_ICON_SLOT_DP free on its right so it never covers buttons, never over full-screen video; a signed-out, still-locked (account number not yet entered) or unlinked app shows no icon and keeps no list; the server returns an empty list to devices not linked to a member (Windows/Mac gate on the unlocked state).
- Every text-entry box stays clear of the on-screen keypad: number-only full screens (account number) never open the system keyboard and type through the in-app NumberPad instead, because a sideways phone leaves no room above a system keyboard; other dialogs go through keepEntryVisible() (top-anchored, ADJUST_PAN, no extract UI, shrunk to the space above the measured IME inset).
- A Live TV preview that reaches playing reports itself as Live TV viewing (np_* now-playing, np_preview flag) until it stops, so it shows on Live connections; the website never credits previews toward viewing hours (watching_preview skips the watch credit).
- Live TV previews never start on highlight (Android: the guide grid's highlight never previews in live mode): the preview box shows the family-on-sofa picture (father pointing a remote at the TV, no text in the picture) until a channel is clicked/OK'd; the instruction line sits under the box (phones title the info "Current programme", show the chosen category under it and put a "▶ Preview channel" button beneath those details); stopPreview shows the picture again. OK again on the previewing channel opens its menu; on phones a single tap on a playing preview opens that menu and the button becomes "▶ Play menu" (previewStarted/previewStopped keep the label in step).
- Report a problem lives on the built-in player screen (top-left button shown with the controls, ADJUST_PAN pop-up, no keepEntryVisible resizing which flickered phones); play menus never carry it — the series page keeps its own button.
- Films/Series on every BM Player (Android MediaHero, desktop MediaHero in app.jsx): details panel on top (backdrop, rating · year · length · genre, cast, director, plot from get_vod_info/get_series_info, cached), Category pill beside Search/Voice at the top (no category column), Sort row, then a full-width poster grid under the category name.
- Playback-engine rules (anti-freeze and live cushion, favourites sync, sound booster, guide listings, DLNA cast, backup hand-over, player controls, EPG time shift) live in `tv-player/app/src/main/java/uk/bmsupport/AGENTS.md`.
- Opening full screen from a playing Live TV preview hands that same ExoPlayer over via PreviewHandoff (no reconnect, one decoder); anything else (other channel, not ready, VLC, catch up) opens fresh after releasing the preview.
