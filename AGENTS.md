# Project Architecture Rules
- Subdirectories have their own `AGENTS.md`; read it before changing files there.
- Authorization, account switching and order/Enabler consumption rules live in `src/lib/AGENTS.md`.
- Public sports guides expose only validated dates, times, event names; cards flag local times on a different UK day.
- Advert slots cycle only BM Support's own affiliate banners in random equal-time order, tracking views and clicks per banner; Member Home and the public landing are separate zones; Fan Zone adds Forum-enabled BM banners to its own.
- Portal homes share one layout: hero image fills the left column; sidebar shows "Hey" + nameplate + role badge, welcome text, then Working Status (staff) or subscription box (members). Staff shows the status pills in the Staff Portal header, right side; members keep the pills in their sidebar.
- Portal Home headers hold alerts; bottom destinations share that header. Rail/editor share scoped saved ordering helpers; status by "Hey", pages in rail, phones use floating menu.
- Back-to-top ignores dialogs/inner panes. Bound Ticket/Talk viewports; mobile ticket headers cap+scroll to keep messages/composers.
- Shared portal headers must wrap the route outlet in a remaining-height flex row; nested page layouts can return sibling columns and must not inherit the header's column direction. A page that renders its own bar must pick the bar of the portal its viewer belongs to, so staff never land on the customer bar.
- Gmail forwarding confirmations: captured by the email receiver, shown only to admins on Bank Transfer.
- Talk: all staff per channel.
- Talk staff cards commit complete refresh snapshots and reserve bounded status/channel space so live updates cannot shift neighbouring rows.
- Ticket staff scope shares one DB predicate across reads, updates and replies: include Orders support, exclude owner-management and order-linked sales to keep list/thread access aligned.
- Talk presence: channel exit broadcasts leave/untracks next task; sign-out removes the shared channel without respawn (no stale online users).
- Staff Away reads user_dnd_status (current window); triggers store shift-linked history.
- Android alerts use per-type tones on versioned channels; sound corrections need a new channel ID because Android retains the first sound.
- Shift reminders use only the scheduled-reminders path; the legacy shift-phone-alerts cron stays disabled to prevent duplicate or post-clock-in alerts.
- Shift sounds deduplicate warning and due phases separately; the shift-over clip plays when the visible still-working question opens, not from a hidden end toast.
- ShiftStartEndAlert owns lifecycle/audio and publishes countdown presentation to ShiftHeaderNotice inside Clocks before Office Time; do not mount duplicate shift controllers in headers or restore bottom warning toasts.
- Guide videos use private storage and short-lived signed links; ordered `video_steps` pair each private video with one visible action.
- Remote-help articles and PDFs share source content in `resources/remote-help-guides`; PDF companion rows use private `guide-files` paths beside existing video rows so adding written guides never replaces Watch actions.
- Install Guides keeps AppTransferPanel's secured APK cards and the Remote Helper guides in the Guides tab, excluding those APKs from general downloads.
- VPN blocking applies only to direct BM registration; link/typed referrals and Fan Zone bypass it; approved referrals skip access-request alerts.
- Ask location opt-in only at the direct BM security gate, never referrals/Fan Zone; refusal blocks ticket requests and tags appeals. Elsewhere capture GPS silently only with existing permission.
- Dialogs fit mobile dvh; dense views drop phone columns. Knowledge Base is full-page with category/ratings rails.
- Video help uses P2P WebRTC and a fixed-size customer canvas; rotation must not reshape or rebuild the encoder (causes black video).
- Gender-matched customer defaults never replace custom picks; staff/Fan Zone-only excluded.
- BM inbox stays separate from Fan Zone/Talk: participant-only tables, authenticated RPCs, admin/management-only report snapshots.
- Seasonal Talk/inbox: one date helper/overlay.
- Dashboard access, header button label and header tab gates come from `src/lib/admin-panel-access.ts`; a header-tabbed page has no tool card.

- Members and role management renders beneath subscriptions in the Customers dashboard tab; legacy member-management URLs redirect there to keep one destination while retaining the existing security gate.
- Break popup/sound shares one session-persisted per-break claim; expiry updates silently to prevent replay after dismiss, lock or reload.
- Fantasy scoring gives full rates only to players who are in the manager's XI AND started the real match (stored per stat row as `started` from the FotMob team sheet); cards are counted from the match timeline as well as player stats, because FotMob's player table often omits them.

- Manual subscription groups use explicit checkout-link customer/account IDs, never site-profile or email matching; admin RPCs validate grouping and renewal targets to keep manual accounts independent.
- Manual credential access verifies email codes plus a salted PBKDF2 PIN atomically; initial enrollment checks an existing paid manual TV login so mailbox access alone cannot enroll or reset a PIN.
- Manual registration exceptions persist on checkout links, enforced by admin-only RPCs and a write trigger; creation saves atomically and PIN access remains independent.

- playSound resolves uploaded overrides for all web callers; closed-app Android tones require an APK rebuild.
- Tests use `bun test` (no Vitest APIs); restore swapped globals.
- Enabler palette/control helpers own appearance; progress reads wizard state, versions use BuildConfig.
- Customer payment notifications contain no passwords; copy actions fetch through an authenticated owner-only read RPC without changing payment methods.
- DB triggers give bannerless sports guides a cover; adverts always render, so every save path keeps both.
- Profit uses pence; unknown fees provisional, known fees fixed. Orders/profit use settled groups; invoice sync repairs rows; demos never affect totals. Stripe retries missing resources across accounts. Pay by bank provider is a server-resolved app setting, GoCardless only when its secrets exist (switch without rebuild).
- Shared planner handles cover exceptions. UK breaks retry empty plans, freeze real times, recheck duplicates. Rota UI/write guards close at UK midnight.
- Cover and swap approvals use authenticated admin/management database functions with a single-slot, owner-context exception for today's rota; swap reassignment and status commit together so ordinary closed-day bookings remain blocked.
- Secure-order video calls: one staff host relays the customer to other staff via a staff-only topic; the session ends only when the last staff leaves, longest-present staff takes over.
- Ticket video: staff-only /video command makes a hashed 30-min token QR to public /video/$token, reusing the secure-order host/relay room.
- Portal: hashed email codes with atomic attempt limits; layout gates content and owns the live timer. User-bound state fails closed; customer portal rail links appear only once unlocked.
- /home redirects by role (`src/lib/portal-home.ts`): staff to /staff-portal, members to /portal; both render `PortalHome`.
- TV Remote: the native helper app authenticates only by a hashed device token at /api/public/tv; staff join the random per-session broadcast topic returned by claim_tv_pair_code, so commands never reach other channels.
- Member-card screen sharing lives in the admin dashboard's member-header slot behind its existing access gates, uses the staff-authorized pairing RPC and RemoteSession viewer, and never appears in Members Directory; order/ticket flows remain unchanged.
- Screen-share navigation resolves linked orders/tickets before mounting generic sessions; scoped pages join the existing host's relay. Overview access is separate from staff help access, preserving staff support while limiting global navigation.
- TV session lists reuse the existing live/history components inside the admin-only Owner Tools section; TV Remote retains requests and its code sidebar to keep session administration separate from connection setup.
- Screen-share request-box actions open the secure checkout Screen share tab for orders and the scoped ticket sharing page for tickets; secure checkout synchronizes its selected tab with navigation search state.
- Active TV screen-share components register a lock keep-alive; the lock conceals and inerts their stable subtree without closing host or viewer peers, while ordinary locked pages still unmount.
- Checkout screen share controls derive ongoing state from the order-private status read; locally ended staff sessions cannot auto-rejoin stale polled rows, so subsequent requests remain available without refresh.
- BM Remote Helper (`tv-remote-helper/`) and BM Remote Control (`tv-remote-control/`) are built in-house on the permanent BM key (the signature-level CONTROL permission links them — keep both on it); Enablers uninstall retired-key pre-2.4/1.1 builds first. Helper is served from `/api/public/remote-helper-apk` via the BM Support app's session installer; the separate control app avoids Android 13+ restricted settings; only the current host forwards commands.
- Fire TV blocks self-ADB (Fire OS 7.6.6.9+/8.1.0.3+, 127.0.0.1:5555 EOF), so remote control is switched on from another device over Wi-Fi ADB (BM TV Enabler, or BM Support Settings › TV remote via `TvRemoteSetupPlugin`).
- Phone APK releases use the permanent signing key and matching Gradle/android-release versions with the bundled asset pointer; the public download proxy is the single destination so existing installs upgrade in place.
- Nav badge realtime channels use a fresh name per mount (drawer and rail coexist; cleanup is async).
- Ticket screen sharing keeps the original thread mounted as the default tab; the layout owns a single customer TV-code dialog reopened from public request messages, successful pairing/connection opens the share tab, and its pop-out only shows public replies so internal notes stay private.
- Order remote installation help goes through tickets: the customer secure order has no setup tabs — a help bar raises a General ticket (office hours only) naming the order reference, and staff connect via the ticket's screen share. `order_remote_setup` stays for legacy/test flows and the shared `/api/public/remote-setup` report; the legacy invitation-gated pairing path remains only for staff test orders, and the standalone customer helper URL redirects home.
- BM TV Enabler (`tv-enabler/`) is PIN-gated and signed with the permanent BM key. Install Guides' QR opens `/api/public/tv-enabler-apk`, selecting the latest available non-Windows build, with one Download button (`?download=1` streams APK); never show an APK card. Over ADB SYNC, install Helper from `/api/public/remote-helper-apk`, then push its `assets/control.apk` directly from the phone to `/data/local/tmp`; never read the Helper's Android/data export (Fire OS blocks it) or use Downloader. Enable steps mirror `TvRemoteSetupPlugin`.
- TV installation skips use exact AndroidManifest package identities cached per APK and a read-only inventory of the selected TV; uploads/replacements refresh identity so app labels never drive skip decisions.
- TV Enabler discovery identifies Fire TVs from local DIAL/UPnP manufacturer/model metadata independently of ADB reachability, holds a multicast lock during scanning, and requires explicit selection; TCP-only reachability never authenticates or enables a TV, so devices with closed debugging remain discoverable without side effects.
- Phone TV ADB clients (`tv-enabler` and BM Support's `tvremote`) stay identical: resend keys on later AUTH and keep pending Allow connections open so AOSP prompts survive.
- TV Enabler confirms a fresh TV check before finishing; website linking optional, stages sync by expiring code; reset keeps RSA authorization. Helper opens once per run; Remote setup has Restart setup.
- Ticket screen-share requests unlock only after the customer's Remote setup is confirmed by a live BM Remote Helper code (server-verified RPC), so staff never invite before the TV app works.
- Enabler references bind to one ticket/order, expire on close (share also on session end), unlink on Restart; apps clear server-expired share codes, never on network errors, keeping install/PIN state. Issuance requires the app protocol marker.
- Renewal is customer-requested and capability-bound to one confirmation; foreground Enabler claims each task once, cold-starts only non-active Helper, then atomically replaces scoped pending-session pointers without extending expiry or approving consent.
- Ticket/order renewal gates persist through tabs and release on replacement or timeout. Their shared instruction wizard is presentation-only; navigation never confirms TV checks.
- Install Guides: route owns device choice; only TV setup and staff help reserve phone/Windows download columns with ticket-bound PIN controls, so guide/video browsing retains the full available width.
- All app download routes call `logDownload` (admin/management-only log; Enabler sends `x-enabler-token`); never blocks downloads, skips resumed ranges.
