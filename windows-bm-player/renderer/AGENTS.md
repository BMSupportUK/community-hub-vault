# Windows BM Player renderer rules
- Movie selections use the full-page MediaHero mode and existing play/resume commands, not the item modal, so description and controls share one destination with preserved browse state.
- Guide rows are memoised GuideRow components with stable handlers, and VideoSurface only reports a changed position from scrolls that move it, so hover/focus and scrolling never redraw the whole guide or flood the main process.
- Multi-screen channel picking uses renderer/multi-picker.jsx (categories + channels with "Now" only, listings loaded per visible row through the shared EPG cache), never the full guide grid; "＋ Add screen" on a single live channel switches to two screens without stopping the playing one. Android's pickMultiChannel mirrors this with category then channel resultList rows.
- Speed: the guide is saved to local storage only after a full load and on exit (never on a timer, which froze the window stringifying the whole guide); never use CSS content-visibility on guide rows or posters (made scrolling worse on Windows).
- Saved-list tabs select both the media filter and its renderer; favourite controls use one shared toggle for previews, playback, item dialogs and parent series so saved channels never render as film posters.
- Radio has a 📻 pill in the existing single-line home row and opens LiveGuide in radioMode: radio-only categories/stations with preview and full screen, but no EPG grid/day controls; ordinary Live TV and guide preloading exclude radio channels through splitRadioChannels.
- Live TV (non-saved lists) renders renderer/live-guide.jsx, mirroring the Android/Amazon box layout: preview + programme info, 24h/Now/Category pills, lazily loaded guide grid; 1st channel click previews, 2nd opens the play menu.
- Live feed pill also shows "Loading channel…" until the first picture is displayed (frame counter or video size), then clears; later stalls use Buffering… so the last picture stays visible.
- EPG listings and single-flight reads live in the signed-in App cache without a channel-count eviction limit; startup/manual refresh load every channel, and scrolling or elapsed time never fetches rows, including empty/failed ones. Login changes clear it; manual invalidation retains old rows until replacement.
- Startup/refresh 'catalogues' events copy only Live TV into the renderer cache; Films/Series are read from the main-process cache when opened, because holding all three crashed the screen on big playlists. A crash reload opens with #resume, skipping the opening film and link screen.
