# Windows BM Player rules
- Main and backup playback share PlayerControls and its 3.5-second input timer; transport and action rows hide together, with content-gated skip/report/swap commands and engine-backed speed/audio/subtitle selection.
- Shared series detail entry focuses its top Back control without scrolling and resets its own pane once per series identity; episode reveal runs only on user focus navigation.
- Programme grid uses guide-axis.cjs for a fixed two-hour/half-hour axis independent of listings, matching Android; short titles truncate to two lines with full details above and in-box reminder bells, so refreshes never change geometry.
- Live TV voice results group only provider category names and channel names independently of typed search, without sports requests; Sports Guide retains its separate event-search.cjs matching.
- Upcoming EPG programme/title and reminder-icon actions open confirmation before any preview selection; title and icon are sibling buttons so mouse and keyboard actions never nest.
- Channel EPG uses fixture-guide.cjs with trusted catalogue names for saved website sports/club fixtures, then provider fallback; ordinary/official stations stay provider-direct. Never restore country imports/category-refresh. Windows and Mac share this path.
- Sports Guide loading presentation covers both the guide request and channel catalog preparation; the shared renderer also serves Mac and clears failed requests instead of leaving an endless wait.
- Sports-pass and high-bitrate recovery (DAZN, Coupang Play, heavy names and device-remembered measured heavy channels via stream-recovery.cjs cushioned) is shared with Mac, using catalog-verified channel/category identity and Sports Guide event context; alternative choices never accept provider URLs from the renderer.
- Windows and Mac never switch or share ts/m3u8 because of buffering; live plays in playlist order, matching Android.
- Live m3u8 keeps the provider's own hold-back (hls.js `liveSyncDurationCount: 2`, never a fixed `liveSyncDuration` seconds offset, which parked short playlists at the oldest segment); a low buffer eases to 0.97 of the user's chosen speed and returns to it, never above it. "Watch on my box" (website What to Watch) is handled in main.cjs `openWatch` from the announcement reply, resolved by watch-request.cjs (provider id, then exact name) and opened through the renderer's own item chooser.
- Windows and Mac share checkin.cjs for staggered website polling, jitter, busy-response backoff and server slowdown; keep stream/provider traffic outside this scheduler.
- Film/series community votes use the unlock-gated main-process bridge; batch poster rating reads and keep shared BM averages separate from provider sort metadata.
- The opening film is bundled offline and rendered before the main screen; the main window is maximised before being shown to avoid a small-window flash.
- This standalone Electron shell uses an isolated React renderer and a narrow, sender-verified IPC bridge; credentials and device tokens stay encrypted in the main process, never in renderer storage.
- Website calls use only the existing device-token `/api/public/player` endpoint; provider requests are built from stored DNS/login, never arbitrary renderer URLs.
- Bundled libVLC runs in-process through the pinned Windows x64 Koffi bridge and renders to BM-owned child HWNDs; never spawn external VLC or expose provider URLs/native handles to the renderer. Validated normalised surface rectangles keep previews, playback controls and dialogs separate.
- Live TV preserves provider channel order; category lists use provider order unless explicitly rearranged in Settings, independently per media kind. Title sorting remains separate.
- Saved-list tabs select both the media filter and its renderer; favourite controls use one shared toggle for previews, playback, item dialogs and parent series so saved channels never render as film posters.
- Approved Windows releases are packaged with @electron/packager and the NSIS script as per-user installers; upload the executable before registering its separate Windows app-build identity, and serve it through the logged Windows download endpoint, never the Android updater.
- Sports matching bundles the website's shared channel matcher rather than copying its normalization rules.
- Windows and Mac sign-in displays the device-token linking code for entry on the website, including legacy locked saved logins; no account-number or retired 2FA screen. Website-verified linked credentials restore access, keeping provider/startup verification gates intact.
- Catch up: provider `tv_archive` live channels carry `archive` days; the guide lists past programmes from `get_simple_data_table` and plays finite timeshift streams, never saved to Recently watched.
- Voice search records 16 kHz WAV in the renderer and sends it through the device-token `voice` action (rate-limited per device, src/lib/player-voice.ts); the AI key stays on the website, never in the app.
- The installer closes BM Player (taskkill + path-matched Stop-Process) and confirms the DLLs are writable before copying, asking Retry/Cancel if still locked.
- Sound booster levels live in sound-boost.cjs (shared with Mac); main.cjs applies boosted libVLC volume only to the audible pane, Mac's <video> engine uses a Web Audio gain node above 100.
- Windows multi-screen silences quiet panes by switching their libVLC audio track off, never with volume/mute: WASAPI shares one volume/mute across every player in the process, so per-pane mute made screens fight.
- Live TV (non-saved lists) renders renderer/live-guide.jsx, mirroring the Android/Amazon box layout: preview + programme info, 24h/Now/Category pills, lazily loaded guide grid; 1st channel click previews, 2nd opens the play menu.
- Every desktop screen mirrors the Android/Amazon app: same navy palette and accent focus ring, home header search pills, tile + separate Refresh button, Sports/Multi-screen/Favourites/Recently watched/Settings row, Films/Series poster screen with Category pill and ⇅ Sort icon after Voice search, film details shown on click, series page with backdrop and one episode row per season; change Android and desktop together.
- Episode cards split the number and title with episode-title.cjs so the number sits on its own line and the title wraps to two lines; provider placeholder names never duplicate the number line.
- BM backup engine (Windows and Mac): backup-switch.cjs moves a screen, once per play, from the main player (Windows libVLC / Mac <video>) to bundled ffmpeg converting to H.264/AAC MPEG-TS on `bmstream://backup-<token>` played by mac-video.jsx; triggered by exhausted reconnects/URLs or a failed start; ffmpeg ships in `tools/ffmpeg` (Mac: `app.asar.unpacked`, universal, signed).

- EPG listings and single-flight reads live in the signed-in App cache, not the disposable guide; login changes clear it and stale rows remain visible during quiet refresh.
- Windows demanding live feeds use hardware-auto decoding; MonoMax, catch-up and unrelated feeds keep software protection. Native surfaces retain the verified decode context on reconnect to avoid reverting demanding feeds to CPU-only decoding.
- Native live freeze recovery uses displayed-picture counters, never the MPEG-TS playback clock, and waits for the live cushion; VLC can display moving pictures while its live clock remains zero.
- Live feed pill also shows "Loading channel…" until the first picture is displayed (frame counter or video size), then clears; later stalls use Buffering… so the last picture stays visible.
- Preview → full screen on the same live channel reuses the running session (main.cjs play) so the filled buffer isn't rebuilt; feed pills sit outside native video surfaces because HWNDs cover HTML.
- Cushioned live feeds (UHD/FHD/DAZN/Coupang) let a buffering pause refill for 20s before reconnecting; a reconnect throws away the 30s cushion, so short pauses must not trigger one. Ended/errored streams still reconnect at once.
- Shared-login takeover: a first stream calls the device-token `stream_claim` (src/lib/player-stream-claim.ts counts other live devices on the same provider login against its max connections); busy returns a "Watch here instead" choice, takeover flags the others via `stream_stop_at`, delivered once in the `announcement` reply. Fails open when the website is unreachable.
- A 401 from the website (device unlinked) runs `unlinked()` in main.cjs: stop every screen, clear login/account/cache and show a fresh link code with an "unlinked" notice; never leave playback running on a removed device.
- Multi/Triple Room logins share automatically: `stream_claim` sends the screens wanted and only prompts when other live devices plus those screens exceed max connections; the device-token `rooms` action lists other watching devices on the same login for the main menu.
- Multi-screen channel picking uses renderer/multi-picker.jsx (categories + channels with "Now" only, listings loaded per visible row through the shared EPG cache), never the full guide grid; "＋ Add screen" on a single live channel switches to two screens without stopping the playing one. Android's pickMultiChannel mirrors this with category then channel resultList rows.
- Multi-screen audio: silent panes are muted (libVLC audio_set_mute / Mac video.muted) and the wanted level is re-applied on every status read, because libVLC drops volume set before audio starts or after reconnects. Startup refresh also preloads the TV guide behind a locked progress screen, capped at 30s.
- Multi-screen reports every pane's channel (joined with ' · ') in stream_claim and poll titles, and each engine's play() keeps that screen's existing sound choice, so reconnects/swaps never re-silence the picked screen or unmute quiet ones. A desktop LinkCheckScreen (family picture, Go to home screen) follows the opening film once per launch, driven by linkVerified.
- Startup/refresh 'catalogues' events copy all three playlists into the renderer's catalogs cache (preloaded), so opening Live TV/Films/Series never re-requests or shows Loading playlist after startup.
- Multi-screen sound changes only on an explicit click/tap or volume change on a pane (never on focus, which the controls watchdog moves); clicks on native pictures use GetAsyncKeyState's pressed-since-last-poll bit, and main.cjs announces the pane via an 'audible' event so the renderer draws its accent border. Multi-screen starts from the front screen only, never a Live TV header pill.
